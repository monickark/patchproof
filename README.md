# PatchProof

Verify that every expected application instance reports the team-approved release using fresh evidence. A different release—even a newer one—is a mismatch. Missing, failed, invalid, or stale evidence is Unknown and never counts as success.

A small portfolio project built with Node.js and plain HTML, CSS, and JavaScript. The hosted experience is simulated; notifications are in-app only. Matching a reported release does not prove security, application health, or an independently verified image digest.

## Get the project

```sh
git clone https://github.com/monickark/patchproof.git
cd patchproof
```

Keep both project folders together:

```text
patchproof-ui/   Dashboard, local HTTP checker, and browser demo
patchproof/      Verification CLI and shared classifier
```

## Run the dashboard

Install Node.js 24 or newer. No package installation is required.

```sh
cd patchproof-ui
./run.sh
```

Open the localhost URL printed in the terminal. To check your own instances, copy `patchproof/config.example.json` to `patchproof/config.local.json`, edit the copy with your endpoint inventory, then run from `patchproof-ui`:

```sh
./run.sh --config ../patchproof/config.local.json
```

The local checker binds to loopback. Keep local endpoint configuration and secrets out of Git. See [dashboard documentation](patchproof-ui/README.md) for the report contract and limitations and [CLI documentation](patchproof/README.md) for CLI usage.

## Build and test

From the repository root, using Node.js 24+:

```sh
cd patchproof
node build.mjs
node --test test/*.test.mjs
cd ../patchproof-ui
node --test test-verification.test.mjs test/*.test.mjs
node test-api.mjs
```

`patchproof/dist` is generated by the CLI build and ignored. **`patchproof-ui/dist` is the dashboard source and is intentionally committed.**
